1 · Why this matters

Everything in ML is just a list of numbers.

A photo. A word. A user. A whole neural network. Underneath, they are all just lists of numbers — what we call vectors. Once you understand the world these vectors live in, every ML algorithm starts to feel like a small geometric story.

Things you already know — turned into vectors

📷

A color photo

A 224×224 photo is just 150,528 numbers stacked together. That is the entire image.

lives inℝ224×224×3
📝

A single word

The word "cat" in a model like BERT becomes 768 numbers. Each captures a tiny piece of meaning.

lives inℝ768
🧠

A neural network

One layer's weights are an m×n grid of numbers. The whole network is one giant point in a giant space.

lives inℝm×n
🎬

You, on Netflix

Your taste is a list of d numbers — one per "hidden flavor" the system has learned about you.

lives inℝd
One picture for the whole lecture
A vector space is the board game ML plays on.
Group = rules for adding pieces.  Vector space = adding + stretching.  Subspace = a valid region of the board.  Independence = no wasted pieces.  Basis = smallest set of pieces that can build everything.  Dimension = how big the board really is.

2 · Groups

A "group" is just a place where adding behaves nicely.

Before we can talk about a vector space, we need a tinier idea: a group. It's the bare minimum for "combining two things gives a sensible third thing." Just a set G and a way to combine any two elements (call it ⊗).

Four rules. That's all a group needs.

G1

Closure — "stay inside"

Combining two things from the set gives back something still in the set. You don't fall out. x + y is still in G
G2

Associativity — "grouping doesn't matter"

It doesn't matter how you bracket: (a ⊗ b) ⊗ c equals a ⊗ (b ⊗ c). (1+2)+3 = 1+(2+3)
G3

Identity — "do-nothing element"

There's a special element e that leaves things unchanged. For adding, it's 0. For multiplying, it's 1. x + 0 = x
G4

Inverse — "undo button"

Every element has a partner that undoes it, taking you back to e. For 5, the partner is −5. 5 + (−5) = 0
Bonus rule: Abelian
If order doesn't matter (a ⊗ b = b ⊗ a), the group is called Abelian. Plain addition is Abelian. Matrix multiplication is not.

3 · Vector Spaces

Group + stretching = vector space.

A vector space is a group of vectors plus the ability to stretch any vector by a real number. It's a place where the two basic moves of linear algebra — add and stretch — always work and never throw you out.

➕

Add (inner move)

Take two vectors. Add them. The result is still a vector. u + v stays in the space.

✦

Stretch (outer move)

Take any vector. Multiply by a real number. 3u or −0.5u — still a vector.

The four rules — in everyday English
V1. The "add" move is an Abelian group: there's a zero, every vector has a negative, and order doesn't matter.
V2. Stretching distributes over adding: λ(u+v) = λu + λv.
V3. Stretches stack up: λ(ψ x) = (λψ) x.
V4. Stretching by 1 changes nothing: 1 · x = x.

Playground · Add and stretch two arrows

Move the sliders. Every λ₁ u + λ₂ v you can build lives inside the same flat plane. That is what "vector space" means.

λ₁ · stretch u1.0
λ₂ · stretch v1.0

Don't get attached to the word "vector"
A "vector" doesn't have to be a column of numbers. A 4×4 matrix can be a vector. A polynomial can be a vector. Even a function can be a vector. Same rules — just different objects. As long as add and stretch behave nicely, you have a vector space.
4 · Subspaces

A space hiding inside a bigger space.

A subspace is a smaller vector space living inside a bigger one. Picture a flat sheet of paper sitting inside a 3-D room. The paper is its own little 2-D world, following the same rules as the room around it.

The subspace test — only 3 things to check
A subset U of a vector space V is a subspace if all three are true:
S1. It contains the origin. (Zero must be inside.)
S2. Closed under add: pick any two things in U, add them, the result is still in U.
S3. Closed under stretch: pick anything in U, multiply by any real number, still in U.
Everything else (associativity, distributivity, …) is inherited automatically.

The one-line rule
In ℝn, the only subspaces are flat shapes that pass through 0: lines through 0, planes through 0, the whole space, and just {0} itself. Anything curved, bounded, or shifted off the origin is not a subspace.

The most useful subspace in ML: the null space

Null space — in plain English
Take a matrix A. Feed it different inputs x. The null space is the set of all inputs that A flattens to zero.
null(A) = { x : A x = 0 }
Think of it as "the directions A can't see." It always passes the subspace test.
Where null spaces show up
Linear regression. Any w in the null space of X doesn't change predictions — that's why we regularize when features are collinear.
PCA. The directions you throw away form a subspace. The directions you keep form another.
Neural network pruning. "Remove this weight" usually means "this direction is in the layer's effective null space — losing it costs nothing."
5 · Linear Combinations & Span

"Where can I get to from here?"

Pick a few arrows. Mix them with any weights — stretch each, then add them all up. The result is a linear combination. Every place you could possibly arrive at is the span.

v = λ₁ x1 + λ₂ x2 + … + λk xk
"a stretch of each arrow, all added up"
Span — the transport-mode picture
Imagine your arrows are transport modes: a train going north-east, a bus going south, a bike going east. The span is every place you can possibly arrive at by combining these modes. Walking backwards counts (that's a negative weight). And here's the kicker: the span is always a subspace.

Three pictures of span

Try each. Notice how adding a redundant arrow doesn't grow what you can reach.

One arrow. Stretch it any way you want — you stay on the line through the origin.

Span in ML
Word embeddings. The span of king, queen, man, woman is a small "concept subspace" inside the giant embedding space. The famous king − man + woman ≈ queen trick lives entirely inside this span.
Linear regression. Predictions ŷ = Xw are vectors inside the column space of X — that's just the span of X's columns.
PCA. Compressing data = projecting onto the span of the top few directions. Smaller span = more compression.
6 · Linear Independence

Are any of my arrows redundant?

If one arrow can be made by combining the others, it's redundant. The set is linearly dependent. If every arrow brings something the others can't replicate, the set is linearly independent.

Linearly independent
The only way to make λ₁ x1 + … + λk xk = 0 is the boring way: every λ = 0. Each arrow brings something new.
Linearly dependent
There exist weights, not all zero, that mix to 0. At least one arrow is redundant — you can rebuild it from the others.

Three pictures of independence

Two arrows in genuinely different directions. Neither is a stretched copy of the other → independent.

Two handy shortcuts
• The zero vector 0 ruins independence instantly. If 0 is in your set, the set is automatically dependent.
• For non-zero arrows: dependent means at least one is a mix of the others. Independent means no arrow can be reconstructed from the rest.

A no-guess test: Gaussian elimination

The recipe
1. Stack the arrows as columns of a matrix A.
2. Reduce A to row-echelon form (just usual row operations).
3. Look at the columns:
   • All columns have a pivot ⇒ independent.
   • Some column has no pivot ⇒ dependent; that non-pivot column is a mix of the pivot columns to its left.

A small example, told step by step

We're handed three arrows as columns of a matrix:

123244

Question: are these three columns independent?

1
Row-reduce

Subtract 2 × (row 1) from row 2:
12300−2

2
Look at the pivots

Pivots in column 1 and column 3. Column 2 has no pivot — it's redundant.

3
Name the redundancy

Column 2 of A is (2, 4) — exactly 2 × column 1. Caught it.

Verdict: the three columns are linearly dependent.
Why ML practitioners chase independence
Data scientists call this same idea multicollinearity. Two columns of your design matrix nearly proportional ⇒ the model has a "ghost direction" it can't pin down. Coefficients become unstable. Fixes: drop the redundant feature, regularize (ridge / L2), or use PCA to project onto a clean independent set. In deep learning, "filter redundancy" inside a CNN is the same idea — duplicate filters waste capacity.
7 · The "recipes" theorem

When you build new arrows from old, what survives?

Imagine you have k trusted ingredients: arrows b1, b2, …, bk that are independent. You use them to cook m new dishes x1, …, xm — each one a recipe of how much of each ingredient to mix.

xj = λ1j b1 + λ2j b2 + … + λkj bk
"Dish j is built from these amounts of each ingredient."

Question: are the new dishes themselves independent, or did we accidentally cook the same dish twice?

The big result
The new dishes x1, …, xm are independent if and only if their recipes (the lists of weights) are independent.
Once you trust the ingredients, checking dishes = checking recipes. We just translate the question into easier coordinates.

The "too many dishes" rule

Pigeonhole — guaranteed redundancy
Each recipe is a list of k numbers — so all recipes live in ℝk. If you cook more dishes than ingredients (m > k), the recipes must have a hidden relation, and so must the dishes. You can't have m > k independent dishes from k ingredients.

A worked example, told as a story

Someone hands us 4 trusted ingredients b1, b2, b3, b4. We cook 4 dishes:

x1 =  1·b1 − 2·b2 + 1·b3 − 1·b4
x2 = −4·b1 − 2·b2 + 0·b3 + 4·b4
x3 =  2·b1 + 3·b2 − 1·b3 − 3·b4
x4 = 17·b1 − 10·b2 + 11·b3 + 1·b4
1
Stack the recipes as columns

Each column is one dish's recipe. Each row is the weight on one ingredient.

 1−4 217 −2−2 3−10  1 0−111 −1 4−3 1
2
Row-reduce
100−7 010−15 001−18 0000
3
Read the pivots

Pivots in columns 1, 2, 3. Column 4 has no pivot. The non-pivot column tells us the recipe-redundancy: the 4th recipe = 7 × first + 15 × second + 18 × third.

4
Translate back to dishes

By the theorem, the same relation holds for the dishes:
7·x1 + 15·x2 + 18·x3 − x4 = 0

The four dishes are linearly dependent — and we caught the exact redundancy.
Why this theorem matters in ML
Dimensionality reduction. Once you pick a small basis (like principal components), every data point is just its recipe in ℝk. ML on the recipes = ML on the originals.
Embedding analyses. "Are 50 word vectors independent in a 32-dim space?" Answer is always no — pure dimension counting (50 > 32).
Capacity arguments. A neural net layer with k neurons can only produce activations in a k-dim subspace. Any m > k outputs must satisfy a linear relation.
8 · Basis & Dimension

The smallest toolkit that builds everything.

Span tells us what we can build. Independence tells us we're not wasting pieces. A basis is the perfect marriage: enough to reach everything, with nothing wasted.

The Goldilocks story
You're at the origin of a flat 2-D map. You want to walk to any point on the map.
🚫 Only north? You reach the y-axis but never go east. Not enough.
✅ North + east? You can reach anywhere. Just right. basis
⚠️ North + east + north-east? Still reaches everything — but "north-east" is a mix of the others. Wasteful. not minimal
A basis = the just-right toolkit. Enough to reach everywhere, nothing wasted.

Four ways to spot a basis (all the same idea)

Way 1

Spans + independent

It reaches everything and has no redundancy. The textbook one.
Way 2

Smallest toolkit

Drop any one piece and you can no longer reach everything. Can't shrink it.
Way 3

Biggest toolkit

Add any new piece and the set becomes redundant. Can't grow it.
Way 4

Unique GPS coordinates

Every vector has exactly one recipe in this basis. Like a GPS for the space.
Why a basis gives unique coordinates
Suppose a vector v had two different recipes in a basis. Subtract the recipes — you get a non-trivial way to mix the basis to 0. But basis vectors are independent, so that's impossible! Therefore the recipe must be unique. "No two ways to be at the same place."

A basis is not unique

The same space ℝ3 can be described by lots of different bases. Pick one — see the building blocks change.

The standard basis — the one we draw by default. e₁ = (1, 0, 0), e₂ = (0, 1, 0), e₃ = (0, 0, 1).

Why "different bases" is one of the most powerful ideas in ML
PCA = "find a new basis for the data, ordered by variance."
Fourier transform = "re-express a signal in the basis of sines and cosines."
Wavelets, ICA, autoencoders = "find a basis where the data's structure becomes obvious."
The data didn't change. The space didn't change. But with a smarter basis, the right algorithm becomes a one-liner.

Dimension

In plain English
Pick any basis of a vector space and count its arrows. Pick a different basis and count again. You'll always get the same number. That number is the dimension — the answer to "how many independent directions does this space really have?"
  • dim(ℝn) = n.
  • dim(ℝm×n) = m · n.
  • If U sits inside V, then dim(U) ≤ dim(V). Equal only if U = V.
Common confusion: components ≠ dimension
Take the y-axis as a vector space. Each vector has 2 components (x and y) — but the space is just a line, not a plane. So its dimension is 1. Components count the room. Dimension counts the actual freedom.
The manifold hypothesis (the ML punchline)
A road on a 2-D map has only 1 dimension of freedom: "how far along the road." The room is 2-D; the road is 1-D. ML calls this intrinsic dimensionality. Real data — images, speech, text — tends to live on a low-dimensional surface inside a huge ambient space. Discovering that surface is most of representation learning.
9 · Finding a Basis

Three steps. Always works.

You're handed a bunch of arrows that span some space. How do you trim them down to a basis?

The 3-step recipe
1. Stack the arrows as columns of a matrix A.
2. Reduce A to row-echelon form.
3. The original arrows whose columns ended up with pivots form a basis.
Important nuance
The basis is the original pivot columns of A — not the columns of the row-reduced matrix. Row reduction tells you which columns to keep, not what they are.

Worked example: a basis for a subspace of ℝ⁵

We're handed 4 arrows, each a list of 5 numbers. They span some subspace U inside ℝ⁵. We don't know yet how big U is, or whether some of these are redundant.

12−1−1−1x1
2−112−2x2
3−435−3x3
−18−5−61x4
1
Stack & reduce

Put them as columns of a 5×4 matrix and row-reduce. Result:

10−13 012−2 0000 0000 0000
2
Spot the pivots

Leading 1's sit in columns 1 and 2. Columns 3 and 4 have no pivots — those arrows are redundant copies in disguise.

3
Read off the redundancies

Column 3 of rref says: x₃ = −1·x₁ + 2·x₂.
Column 4 of rref says: x₄ = 3·x₁ − 2·x₂.
So x₃ and x₄ are nothing more than mixes of x₁ and x₂.

The result
A basis of U is just {x₁, x₂}. So dim(U) = 2.
The picture: U lives inside ℝ⁵ (a 5-D space) but is itself only 2-D — a flat plane through the origin. Our 4 original arrows all lay on this plane. The plane needs only 2 directions to describe.
Connection to model capacity
The number of pivots is the rank of the matrix — the dimension of its column space.
• For a feature matrix X, rank(X) tells you how many features are truly independent.
• For a neural-net weight matrix W, rank(W) caps the "effective directions" the layer can express. LoRA and other low-rank tricks explicitly exploit this.
• For a Jacobian J, rank(J) tells you how many input directions actually affect the output.

11 · Practice

Five problems to lock it in.

Try each in your head, then expand the solution.

Problem 1 — Subspace test of ℝ³

Which of the following are subspaces of ℝ³?

  • (a) { (x, y, z) : x + y + z = 0 }
  • (b) { (x, y, z) : x + y + z = 1 }
  • (c) { (x, y, z) : x ≥ 0 }
  • (d) { (x, y, z) : x = 2y }

Hint: anything that fails closure under negative stretching, or doesn't contain 0, is out.

Answer. (a) Yes — passes through 0, closed under add and stretch. (b) No — doesn't contain 0. (c) No — fails when you stretch by a negative number. (d) Yes — a plane through the origin.
Problem 2 — Express as a linear combination

Write b = (4, 3, 1, 2) as a linear combination of v₁, v₂, v₃, v₄.

Hint: set up the augmented system [v₁ v₂ v₃ v₄ | b] and row-reduce. Read off the weights.

After row-reducing, the right-hand side gives you the weights λ₁, …, λ₄ directly. It's the same procedure as solving any Ax=b.
Problem 3 — Recipes theorem in action

Let b₁, b₂, b₃ be linearly independent. Define x₁ = b₁+b₂,  x₂ = b₂+b₃,  x₃ = b₁+b₃. Are the new x's independent?

Answer. By the theorem, just check the recipes. They are (1, 1, 0), (0, 1, 1), (1, 0, 1) as columns. Stack and row-reduce: all three columns get pivots → the recipes are independent → so are x₁, x₂, x₃.
Problem 4 — Is it a basis?

Is { (2, 3, 5), (5, 7, 9), (1, 11, 1) } a basis of ℝ³?

Answer. Stack as columns and row-reduce. If all three columns have pivots, the set is independent. Three independent arrows in a 3-D space are automatically a basis (no need to check spanning separately — the dimension argument does it for free).
Problem 5 — Find a basis

Find a basis (and the dimension) of the subspace of ℝ⁴ spanned by (1,2,1,3), (2,4,2,6), (1,0,1,1), (3,2,3,5).

Answer. Notice column 2 = 2 × column 1, and column 4 = column 1 + column 3 — both obvious from inspection. Row reduction confirms: only columns 1 and 3 are pivots. So a basis is { (1,2,1,3), (1,0,1,1) } and the dimension is 2.

Vector spaces are the stage. Linear independence is the casting. A basis is the cast. The rest of ML is the play.
